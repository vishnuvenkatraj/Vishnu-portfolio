# MongoDB Atlas Integration & Setup Guide

This developer portfolio is integrated with **MongoDB Atlas** to securely persist contact form inquiries submitted through the interactive website.

---

## 🏗️ Architecture Overview

```
[Visitor Browser]
       │
       ▼ (POST /api/contact)
[Next.js Server-Side Route Handler]  (src/app/api/contact/route.ts)
       │
       ├─► 1. Validate & Sanitize Input (src/lib/sanitize.ts)
       ├─► 2. Connect via Cached Mongoose Manager (src/lib/mongodb.ts)
       └─► 3. Save Structured Document (src/models/ContactMessage.ts)
              │
              ▼ (TLS / SSL Encrypted over mongodb+srv://)
       [MongoDB Atlas Cloud Cluster]
              └─► Database: portfolio
                     └─► Collection: contact_messages
```

- **Zero Client Credential Exposure**: MongoDB connection strings are strictly kept on the server. No `NEXT_PUBLIC_` variables are used.
- **Connection Caching**: Reuses active Mongoose connections across hot reloads in development and serverless invocations in production to prevent connection exhaustion.
- **Data Validation & Sanitization**: Strips HTML tags and script injections (stored XSS prevention) and validates email formatting (RFC 5322).

## 🚀 Step-by-Step MongoDB Atlas Setup Guide

### 1. Create a MongoDB Atlas Cluster (Free Tier)
1. Sign in or register at [MongoDB Atlas](https://www.mongodb.com/cloud/atlas).
2. Click **Create** to deploy a new database.
3. Choose the **M0 Free** shared cluster (512MB storage, permanently free).
4. Select your preferred cloud provider (AWS, GCP, or Azure) and the closest geographic region.
5. Click **Create Deployment**.

---

### 2. Configure Database Access (User Credentials)
1. In the MongoDB Atlas sidebar, navigate to **Security** → **Database Access**.
2. Click **Add New Database User**.
3. Set **Authentication Method** to **Password**.
4. Choose a username (e.g. `portfolio_admin`) and a secure password.
5. Under **Database User Privileges**, select **Read and write to any database** (or restrict to `portfolio`).
6. Click **Add User**.
   *(Save your password securely; you will use it in the connection string).*

---

### 3. Configure Network Access (IP Whitelist)
1. In the sidebar, navigate to **Security** → **Network Access**.
2. Click **Add IP Address**.
3. For local development and serverless deployment platforms (such as Vercel, Railway, or AWS):
   - Click **Allow Access from Anywhere** (`0.0.0.0/0`).
4. Click **Confirm**.

---

### 4. Retrieve Your Connection String
1. In the sidebar, click **Database** to view your clusters.
2. Click the **Connect** button next to your cluster.
3. Choose **Drivers** (Node.js).
4. Copy the connection string format:
   ```text
   mongodb+srv://<username>:<password>@<cluster-url>/?retryWrites=true&w=majority&appName=Cluster0
   ```
5. Specify the database name (`portfolio`) right before the query parameters `?`:
   ```text
   mongodb+srv://<username>:<password>@<cluster-url>/portfolio?retryWrites=true&w=majority
   ```

## 🔑 Environment Variable Configuration

### Local Development (`.env.local`)
Create or edit the `.env.local` file in your project root:

```bash
# .env.local
MONGODB_URI=mongodb+srv://YOUR_USERNAME:YOUR_PASSWORD@your-cluster.mongodb.net/portfolio?retryWrites=true&w=majority
```

> [!IMPORTANT]
> - Replace `YOUR_USERNAME` with your MongoDB database user.
> - Replace `YOUR_PASSWORD` with your user's password (if the password contains special characters like `@`, `#`, or `/`, URL-encode them).
> - Never commit `.env` or `.env.local` to git. Both files are strictly ignored in `.gitignore`.

### Production Deployment (e.g., Vercel)
1. Go to your project dashboard on Vercel (or your hosting provider).
2. Navigate to **Settings** → **Environment Variables**.
3. Add the variable:
   - **Key**: `MONGODB_URI`
   - **Value**: `mongodb+srv://YOUR_USERNAME:YOUR_PASSWORD@your-cluster.mongodb.net/portfolio?retryWrites=true&w=majority`
4. Redeploy your project.

## 📋 Data Schema (`ContactMessage`)

All incoming submissions are saved to the `contact_messages` collection using this structured schema:

| Field | Type | Required | Constraints / Description |
| :--- | :--- | :--- | :--- |
| `name` | `String` | Yes | Trimmed, 2–100 chars, sanitized. |
| `email` | `String` | Yes | Trimmed, lowercase, RFC 5322 regex validation, max 254 chars. |
| `subject` | `String` | No | Trimmed, max 200 chars. Default: `"Portfolio Contact Inquiry"`. |
| `message` | `String` | Yes | Trimmed, 5–5000 chars, HTML-sanitized. |
| `status` | `String` | Yes | Enum: `unread`, `read`, `archived`. Default: `"unread"`. |
| `ipAddress`| `String` | No | Extracted from `x-forwarded-for` / `x-real-ip` (security tracking). |
| `userAgent`| `String` | No | Client browser User-Agent header. |
| `createdAt`| `Date` | Auto | Generated by Mongoose timestamps. |
| `updatedAt`| `Date` | Auto | Generated by Mongoose timestamps. |

## 🧪 Testing the Integration

### 1. Automated Test Suite
Run the test suite to verify input sanitization, security rules, and validation logic:

```bash
npm run test:db
```

### 2. Manual Test Submission via cURL
With the development server running (`npm run dev`), test the API directly:

```bash
curl -X POST http://localhost:3000/api/contact \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Jane Doe",
    "email": "jane@example.com",
    "subject": "Internship Inquiry",
    "message": "Hello Vishnu! I would like to discuss an opportunity."
  }'
```

Expected Response:
```json
{
  "success": true,
  "message": "Thank you! Your message has been received and securely stored. I will get back to you shortly.",
  "id": "67375a..."
}
```

### 3. Testing via Portfolio Website UI
1. Start your dev server: `npm run dev`
2. Scroll to the **Get in Touch** section at the bottom of the page.
3. Fill out the Name, Email, and Message fields and click **Send Message**.
4. Observe the interactive loading state ("Sending Message...") and the confirmation notification ("Message successfully received!").
5. Log into [MongoDB Atlas](https://cloud.mongodb.com) → **Database** → **Browse Collections** → `portfolio` → `contact_messages` to view your new record!
